**OpenSpec 2.1.1，实跑核实的做法。**

- `openspec new change <名>` 只建 `openspec/changes/<名>/.openspec.yaml`。
- 四件产物：`proposal.md`、`specs/<能力>/spec.md`、`design.md`（可缺）、`tasks.md`。
- 待办的数法在安装目录的 `dist/utils/task-progress.js`，原始规则是：

  ```js
  /^\s*(?:[-*+]|\d{1,9}[.)])\s*\[(?:\s*([^\]\s]?)\s*\](?![([])|\s+\])\s*(.*)/
  ```

  换成人话：以列表符号或数字编号开头的行，后面跟着方括号，方括号里是空的或只有一个字符，并且右方括号后面不是紧跟圆括号，就算一条待办，缩进的子项也算。方括号里多于一个字符的不算（如 `[WIP]`）。右方括号后面紧跟圆括号的是链接，不算（如 `[说明](./a.md)`、`[](./a.md)`）；只有方括号里是空白时才算（如 `[ ](./a.md)`）。代码围栏里的行照算。捕获到的那一个字符是 `x` 或 `X` 才算勾完。状态只有三种：没有待办、进行中、完成。
- 归档后的目录是 `openspec/changes/archive/YYYY-MM-DD-<名>/`。
- `openspec init --tools zcode --scope project` 生成 `openspec/config.yaml`、`openspec/specs/`、`openspec/changes/archive/` 和 6 个技能（`.agents/skills/` 和 `.zcode/skills/` 各一份）。它不碰根 `AGENTS.md`。页面只提示 `openspec init`，不指定工具和范围，怎么调用由用户自己决定（第 9 轮人定）。
- 归档会把规格增量并进 `openspec/specs/`，需求标题下的出处行会跟着并进去。人定了：归档后把主规格里的出处行去掉（第 9 轮）。

**浏览器约束。** 读写目录靠 File System Access API。

- 只有 Chrome、Edge 支持。选目录和申请权限都必须由用户的点击触发。
- 目录句柄可以存进 IndexedDB，刷新后还在。浏览器重启后权限失效，要用户再点一下。
- 按字节读文件时注意：不带 BOM 的 UTF-16 可能恰好是合法的 UTF-8（西文后面跟一个零字节），严格解码拦不住。正文里有零字节就不是 UTF-8 文本。
- 浏览器自己的存储（IndexedDB、localStorage）可能读不了或写不进去（被设置禁掉、存满）。记住目录和最近项目存在这里，读不了、写不进去时照常工作。
- 项目目录在磁盘上被删除以后，对它的句柄再迭代条目，报「找不到」（`NotFoundError`）。出处是 File System Access 规范第 2.4.1 节：找不到条目就这样拒绝（2026-11-24 查）。被移动、改名的情况规范没规定，以真机为准。
- Chromium 往真实目录写文件时拦三类文件名：固定封 `lnk`、`scf`、`url`；封 CLSID 形状的扩展名；查 Safe Browsing 的下载文件类型表，标为危险的才封（`.local` 例外）。2026-11-23 查到表里标为危险的是 `cfg`、`dll`、`ini`、`manifest`、`dng`、`scf`、`local`。它同时查文件名合不合法，不只查扩展名。标为「手势允许」的不封，所以 `.py`、`.js`、`.sh`、`.bat` 不被拦；`.md` 在表里但不危险，`.yaml` 不在表里，现在框架名单上的 10 个文件安全。表里标为危险的扩展名带平台：`cfg`、`dll`、`ini`、`manifest`、`scf` 只在 Windows 上算危险，`dng` 只在 Android 上。oh my task 自己的检查从严，不分平台都拦。这张表随 Chromium 版本和 Safe Browsing 配置变。旧版真机上还遇到过 `.bak` 写不进去（T0043，11 月 5 日），当前表里没有它，原因没查到，知识库按「源码表加真机证据的并集」记。这台机器连不上 Chromium 的源码站，连得上 GitHub 上的镜像 `chromium/chromium`，三个文件的位置见待办 5.5。单元测试用的内存沙箱复现不了，只有真实目录句柄会触发。

## Goals / Non-Goals

**Goals:**

- 一个纯前端静态网页：切换目录、四列看板、初始化、更新。
- 内置的那套只有一份正本，就是 oh-my-task 仓库里的文件。
- oh-my-task 仓库成为任务系统的源头，也是第一个业务项目。

**Non-Goals:**

- 不另记任务状态。卡住、等人答 AI 假设、拷问中，页面都看不到。
- 不启动、不唤醒 AI 会话，不收人的决定。
- 不管理 OpenSpec 自己的文件，不代跑 `openspec init`、`openspec update`。
- 不做版本号、哈希比对、备份、防降级。
- 不做流程画布、新手指南、跨项目队列。
- 不迁移已装旧版 `.oht/` 的业务项目，不决定 memos 的去留。

## Decisions

### 1. 纯前端，文件即真相

页面知道的只有业务项目目录里的文件，每 5 秒重读一遍。不做本地服务，因为新需求里没有一样要后端（旧版经验，2026-11-03 人定「弃本地薄服务」）。代价见 Risks。

每 5 秒重读一遍，带来几条规矩：

- 写完文件（初始化、更新）以后，先等正在进行的那一轮读完，再读一轮。那一轮读到的可能是写以前的文件，不等的话更新完反而显示「有更新」。
- 重读成功只清读文件的错。写文件失败的提示留到人照提示处理为止，也不被读文件的错盖掉。
- 开着的卡片详情跟着重读。读不出来、那张卡没了、换了页面，就关掉抽屉。先后点开两张卡时，先点的那一轮晚结束也不许覆盖后点的。
- 每次重读先看项目目录本身还在不在。被移动、改名或删除以后，句柄取什么都是「找不到」，不说的话会被当成一个空目录，页面错显示成「还差一步」。只有「列不出项目目录本身」才算打不开；任务夹读到一半被删了也报「找不到」，那种下一轮重读就好。
- 目录打不开了就放下它：说清是哪个目录，从最近项目里拿掉，「继续打开」也不再提它。
- 「记住目录」和「最近项目」存在浏览器自己的存储里，只是为了下次方便。存储读不了、写不进去时照常工作：能选目录就选，能打开就打开，不停在空白页。这类失败只记进控制台。兜底要从最外层包起：浏览器禁止站点存数据时，连取 `localStorage` 本身都会抛错；存储事务被中止时（磁盘满）只发「中止」事件、不发「出错」事件，两样都要接住，否则要么停在空白，要么永远等下去。
- 先打开目录，打开成功了才在后台记住它：存储要是卡住，不能连选好的目录都打不开；打开时发现目录已经不在了的不记，只是这一次没读出来的照记（之后点「重试」能打开）。启动时、点「继续打开」时等浏览器存储最多 2 秒。启动时等不到就当没存过；点「继续打开」时等不到只按「打开没成功」处理，点「重试」会再取一次，不把记录当成没了（那会顺手删掉它）。
- 「记住目录」的两条记录（目录本身、「上次打开的是它」）写进同一个事务，要么都记上，要么都没记。
- 清存储记录是放在后台做的（要走一趟浏览器的数据库），页面先更新，不等它。
- 目录打不开了，会话编号跟着加一：这个项目还没做完的事（比如正在写的更新）回来一看编号变了，结果就丢掉，不会盖掉「打不开了」这句话。

### 2. 直接内置，加一份框架名单

- 框架名单在 `app/src/framework/manifest.ts`。每一项是仓库里的路径，加一个 `?raw` 导入。不写生成脚本。
- 现在的框架名单共 10 个文件：
  - `.omt/AGENTS.md`
  - `.omt/工作流/默认工作流.md`
  - `.agents/skills/grill-with-docs/` 下全部（`SKILL.md`、`agents/openai.yaml`）
  - `.agents/skills/grilling/` 下全部（`SKILL.md`、`agents/openai.yaml`）
  - `.agents/skills/domain-modeling/` 下全部（`SKILL.md`、`GLOSSARY-FORMAT.md`、`ADR-FORMAT.md`、`agents/openai.yaml`）
- 要加一个文件，就在框架名单里加一行。
- 测试读仓库的真实文件，核对三件事：每个名单项与磁盘逐字一致（换行归一后）；内置内容里没有回车符；三个技能目录里没有漏掉的文件。归一函数另用含 CRLF 的字符串单测。2026-11-23 和 24 各查过一次，`grilling/` 下两个文件是 CRLF，其余八个是 LF，以实施时实测为准。
- 换行：导入后把 `\r\n` 归一成 `\n`。`.gitattributes` 同时把框架文件设成 LF。
- 开发服务器默认只放行 `app/`，要在 Vite 配置里放行仓库根，否则开发时读不到 `.omt/`。放行以后要写拦截名单，挡住 `.git/`、`.zcode/`（后者里有 memos 的密钥）。Vite 拿文件的绝对路径去匹配名单：不带斜杠的模式它自动加上前缀，带斜杠的要自己写全，`.zcode/` 要写成两颗星加斜杠开头的样子（见 `app/vite.config.ts`）。2026-11-24 实测过：写成 `.zcode/` 加两颗星的那种，一条都拦不住。
- 框架文件每改一次都要重新构建、重新部署网页。接受。
- 框架名单上的文件名要合法，扩展名不能在 Chromium 的拦截名单上。名单怎么来见 Context 和待办 5.5，测试按它断言。

### 3. 阶段全部推导，不存任何状态

每个任务夹读一次文件就能定它在哪一列：

| 列 | 判定 |
|---|---|
| 需求 | `tasks.md` 不存在，待办数为 0，或一条都没勾 |
| 执行 | 已勾的大于 0，少于总数 |
| 等你验收 | 已勾等于总数，且总数大于 0 |
| 已归档 | 目录在 `openspec/changes/archive/` 下 |

- 拆任务并进建任务夹以后，待办在需求阶段就写好了，所以用「有没有勾过」区分需求和执行（第 10 轮人定）。剩下一种分不出来：任务被打回需求阶段，但已勾的待办还在，这时它仍显示在「执行」列。
- 待办解析用 Context 里那条原始规则，不自己写。
- 已归档的名字去掉开头的 `YYYY-MM-DD-`，按这个日期从新到旧排。`archive` 目录本身、`changes/` 下的非目录项一律忽略。
- 「多久没动」取任务夹里所有文件的最新的修改时间。不到 1 分钟显示「刚刚」，然后依次是「N 分钟没动」「N 小时没动」「N 天没动」。
- 出处：从任务夹的 `specs/**/*.md` 里找 `### Requirement:` 行，取紧随其后的第一行；去掉开头的引用符 `>` 和空格以后，以「出处：」开头的才算。从 `proposal.md` 里取「## 拷问记录」到下一个二级标题之间的表格行。
- 轮询用同一个读取函数，手动刷新也调它。上一次没读完就不开始下一次。

### 4. 置入和覆盖共用一个规划函数

- `planInstall(框架名单, 读目标目录的接口, 模式)` 是纯函数，返回「拒绝的原因」或「要写的文件、要建的目录」。
- 模式是初始化时，按顺序查三样，任何一样不通过就拒绝，并且一个文件都不写：
  1. 目标有 `.oht/`。
  2. 目标有 `.omt/`。
  3. 框架名单上的文件在目标里已存在。不论内容是否相同都算，因为正常情况下不该出现同名文件。
- 被第 3 样拒绝时，用显眼的警告块列出冲突的文件，不用一行小字。人要求一定看得到。
- 模式是更新时不查冲突，框架名单上的全部都写。
- 两种模式都处理根 `AGENTS.md`：不存在就新建；存在且不含 `.omt/AGENTS.md` 就在开头插入口块；已含就不动。入口块只有一行：

  ```text
  开始任何工作前，先读 `.omt/AGENTS.md`（任务系统在本项目的说明）。
  ```

- 根 `AGENTS.md` 是唯一会被改写的已有文件，又不备份，所以已有的文件按字节读：认得出 UTF-8 才改，带不带 BOM 都行，带 BOM 的把 BOM 留在最前面。认不出就拒绝，一个文件都不写，提示另存成 UTF-8。只有「编码不对」这一种错才算认不出；读根 `AGENTS.md` 时的别的错（没权限、它其实是个目录）原样按出错处理，不说成编码不对。认不出的有两种：字节不合 UTF-8 的（带 BOM 的 UTF-16、含中文的 ANSI），靠严格解码拦；字节恰好是合法 UTF-8 的（不带 BOM 的 UTF-16，西文后面跟一个零字节），靠「正文里有零字节」拦。只有英文的 ANSI 文件本来就是 UTF-8，照常。
- 两种模式都让空目录 `.omt/术语/`、`.omt/知识库/` 存在，它们在返回值的「要建的目录」里：初始化时建，更新时缺了就补。初始化可能失败在建目录那一步。
- 权限一次申请完：选目录用读写模式，「继续打开」时的重新授权也是读写一起。初始化和更新不再另外申请（第 9 轮人定）。
- 全程不调用任何删除接口。测试断言要写的文件里没有拦截名单上的扩展名。

### 8. 测试分两层

- 单元测试（vitest）：解析、推导、规划、入口块、比对、最近项目、时间的人话，全部是纯函数的表驱动测试。组件测试注入内存里的假目录句柄。展示路径的测试里，假句柄的写方法一被调用就报错。
- 真机：权限、Chromium 拦截、选目录，这三样单测复现不了，由人按 tasks.md 末尾的真机验收单验收。
- 修验收指出的问题时补的测试，补完做一遍变异检查：把修复临时撤掉再跑，对应的测试要红。撤了还绿，说明没测到点上。
- 开发服务器的拦截名单有一条回归测试（`app/src/devserver.deny.test.ts`），它起一个真的开发服务器去要文件。

### 9. 技术选型

React、TypeScript、Vite、antd、zustand，测试用 vitest 和 Testing Library。理由是需求小，哪个框架都够用；人对 antd 这套界面给过几十轮反馈；换框架等于作废这些经验。版本用实施当时的最新版，不从旧代码里抄任何一行。折叠的文档显示原文，不引排版库。

### 10. 分支、提交、推送、部署

在分支 `redesign` 上做，本地提交自动做。验收通过后合并回 `master` 再推送（先问人）。推送触发 GitHub Actions：构建并发布到 GHCR，标签是 `latest` 和提交号。服务器换容器（先问人）。本机没装 docker，Dockerfile 只能靠 Actions 验证。

镜像的构建上下文是仓库根，Dockerfile 在 `app/Dockerfile`。原因是页面要用 `?raw` 读 `app/` 之外的 `.omt/` 和 `.agents/skills/`，沿用旧版的 `context: ./app` 会构建失败。本地构建用 `docker build -f app/Dockerfile .`；Actions 里写 `context: .` 和 `file: app/Dockerfile`。仓库根放 `.dockerignore`，至少排除 `.git`、`app/node_modules`、`app/dist`、`.zcode`。

## Risks / Trade-Offs

- **常开的旧标签页会把旧文件覆盖回去。** 不做防降级。确认框里提醒一句；覆盖回去以后刷新页面再更新一次就恢复。接受。
- **Chromium 对真实目录的限制测不出来，拦截名单也不全。** 靠真机验收单；实施时查清名单。
- **项目文件夹被移动或改名以后，浏览器对留下的句柄报什么错，规范没规定**（被删除的报「找不到」，见 Context）。页面按「找不到」处理；真机验收单里有一步专门确认，报的不是这个的话回来改。
- **清掉「目录记录」是按名字删的。** 浏览器的数据库要是慢到几秒，人已经把同名目录重新选了，旧的那次清理会把新记录也删掉。后果只是下次没有「继续打开」，要重新选目录。接受。
- **框架文件每改一次都要重新部署。** 接受，这是直接内置的代价。
- **只能用 Chrome、Edge，浏览器重启要点一下。** 接受。
- **页面分不出来的状态。** 卡住、等人答 AI 假设、拷问中，页面都看不到；任务被打回需求阶段而已勾的待办还在时，仍显示在「执行」列。接受。实践证明疼了，由人先提，再加。
- **源头删掉的框架文件，更新认不出来。** 更新对它什么都不做，不删也不列。接受。
- **任务夹和代码不在一个仓库。** 根 `AGENTS.md` 写明任务夹在哪。归档后搬迁，这个状态就结束了。

## Migration Plan

1. 在 oh-my-task 仓库开分支 `redesign`。一个提交删掉旧内容（连同不在 git 里的 `app/node_modules`、`app/dist`），一个提交落框架文件和新的根文件。
2. 做页面。本地提交自动做。
3. 页面能跑以后，人按真机验收单验收。验收单里有一步是用新页面对工程 1 点「更新」。
4. 验收通过：合并回 `master`，推送（先问人），Actions 发布镜像，服务器换容器（先问人）。
5. 归档后另做：把工程 1 的术语、长期决策、知识库、归档的任务夹搬进 oh-my-task 仓库，再删除工程 1。

回退：旧内容都在 git 历史里，检出旧提交就能拿回。线上的旧镜像在换容器之前一直在。
