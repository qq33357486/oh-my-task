# 工具开发 · 业务工作流

> 状态：草案（2026-11-24；来源：任务夹 redesign-oh-my-task 走通的做法；验证案例：redesign-oh-my-task 一个，第二个任务走通后转正）。
> 边界：管「给 oh my task 这个网页工具加功能、改造」这类任务。只接手默认工作流的执行阶段；需求阶段和整理归纳阶段照默认工作流。
> 上下游：上游＝独立审查通过的任务夹；下游＝`app/` 里的代码和测试、本地提交。

## 流程（执行阶段）

1. **读**（AI）：读项目规则、任务夹的 design.md（里面有做法和实跑核实的事实）、`app/src/framework/manifest.ts`（框架名单）。
2. **做**（AI）：一组待办一组地做，每组做完本地提交一次。不碰文件的逻辑先写成纯函数：解析、推导、规划、比对都是；读写文件通过参数注入。做完一项勾一项。
3. **测**（AI）：每个纯函数配表驱动的测试。页面测试注入内存里的假目录。展示路径上的测试，把假目录设成一写就报错。为了修验收指出的问题补的测试，补完把修复临时撤掉跑一遍：对应的测试会红才算数，撤了还绿说明没测到点上。核对「是不是同一个项目」这类到处都有的小防护也算，逐处撤。全量按顺序跑几遍，再乱序跑几遍（`npx vitest run --sequence.shuffle`）。
4. **查构建**（AI）：新模块只有被页面引用了才会进构建包。新增内置内容之后，跑 `npm run check:bundle`（先 `npm run build`），在生产包里逐个找框架文件的内容，10 个都找得到才算数。
5. **独立验收**（新开的 AI）：对照任务夹和项目规则核。读写真实目录的行为单测覆盖不到 Chromium 的限制，留给人在真实浏览器里点。验收不过就回到第 2 步，改完重新验收。

涉及外部规则的（OpenSpec 怎么数待办、Chromium 拦哪些文件名），先实跑或读源码核对，再写进测试当期望值；核对的办法和日期写进注释或知识库。

## 规则

- 读写目录的接口只写在 `app/src/fs/` 这一层，别处只认这层接口，不直接碰浏览器的目录句柄。
- 提交自动做。推送到 GitHub、在服务器上换容器，先问人。
- 三个拷问技能是框架文件，定期从上游仓库 <https://github.com/mattpocock/skills> 更新。grilling 直接用上游的；domain-modeling 有本地改动（文件位置改到了 `.omt/术语/`），更新时合并进去。更新后跑框架名单的测试。
- 框架文件改了，要重新构建、重新部署网页，各业务项目再点一次「更新」。
- 开发服务器为了读 `app/` 外面的框架文件，放行了整个仓库根。`.git/`、`.zcode/` 靠 `vite.config.ts` 里的拦截名单挡住，改了 `server.fs` 要看 `src/devserver.deny.test.ts` 过不过（它会起一个真的开发服务器）。

## 强制

1. 待办的数法、文件拦截名单这类外部规则，不许自己另定。以 OpenSpec、Chromium 的实际行为为准，它们变了要回来同步。
2. 展示路径不许写任何文件。除了初始化和更新，页面不碰业务项目。
3. 初始化遇到同名文件一律停下，一个文件都不写。

## 禁止

1. 禁止往框架名单里放浏览器拦着不让建的文件。名单在 `app/src/framework/blocklist.ts`，来历见工程 1 知识库「浏览器拦截的文件名」。
2. 禁止为了让测试通过去改外部规则的期望值。期望值和外部行为对不上时，先查是谁变了。
3. 禁止在本工作流里改默认工作流。要改默认工作流，另起任务。

## 常见错误

| 现象 | 修正 |
|---|---|
| 判断「目录在不在」用了「文件在不在」的接口，永远判成没有 | 目录和文件各有一个判断；每条拒绝的分支都要有对应用例 |
| 长文件用命令行写，被截断在半截，后面的命令也没跑 | 长文件用写文件的工具，命令行只跑短命令 |
| 检查脚本在「一条都没找到」时也打印成功 | 先断言找到的数量等于预期，再说通过 |
| 假目录带着函数，存不进 IndexedDB，一打开目录就报错 | 测试里把「记住目录」换成内存里的替身。真句柄能存，这件事只在浏览器里成立 |
| 假时钟是在轮询启动之后才装的，拨快时钟拨不到 | 先装假时钟再渲染；只替换 `setInterval`，把 `setTimeout` 留给测试框架 |
| 一口气拨快很多轮，轮询只多了一次 | 上一轮没读完不开始下一轮，这是设计。测试要一轮一轮地等 |
| 按钮是两个汉字，antd 自动在中间加空格，按名字找不到 | 测试里写成「刷 ?新」这样的匹配 |
| 查一段带空行的原文，文本查询把空白折叠了，查不到 | 用函数逐字比对 `textContent` |
| 点「取消」后想用「弹窗不见了」来判断，动画在测试环境里播不完 | 直接断言回调没被调用、数据没变 |
| 测试里把 store 的函数换成了假的，污染后面的测试 | 用 spy 包住真函数，用完恢复；每个测试前重置数据字段 |
| 名单模块没被任何代码引用，构建包里找不到它的内容 | 接上引用再查；查的时候确认抽样数量对得上 |
| 读取一层、显示一层，各自的单测都过，合起来才露馅（读取时把总数截掉了） | 跨层的东西要有一个从读取到显示的测试，别只靠两头各自的测试 |
| 页面的切换只做了一个方向（能进「还差一步」，回不了看板） | 每种页面切换都写两个方向的测试 |
| 测试里模拟故障的开关一直开着，后面「重试」那一步当然还是失败 | 重试之前把开关关掉 |
| 测试直接摆好了页面状态，卡片却不出现 | 真实流程里打开项目时会读一次；测试里要手动触发那一次读取 |
| 普通的 node 脚本去引用带 `?raw` 导入的模块，报不认识的文件扩展名 | 脚本里不引用它，按同一条规矩从磁盘上找 |
| 新版 antd 把一些属性改了名（Alert 的 `message` 改成 `title`，Drawer 的 `width` 改成 `size`），测试时满屏警告 | 升级依赖以后看一眼测试输出里的警告，逐个改掉 |
| 换项目时上一个项目的状态没清干净（「有更新」、回话），结果在一个不该写的页面上能触发写入 | 属于项目的东西列成一份清单，每次打开项目统一清掉。会写文件的操作要按「当前是哪一页」守卫，不能只看手里有没有目录 |
| 读到一半换了项目，上一轮读到的卡片写进了新项目 | 每次打开项目记一个编号；读完核对编号，对不上就丢掉结果 |
| 修一个问题的时候带出新问题（加了「有更新」和「重试」以后，它们在别的页面上也生效了） | 改完状态的流转，把「项目甲 → 项目乙」和每种页面切换的两个方向都测一遍 |
| 自动发布不跑测试，「构建前的测试报错」只靠人记得先跑 | Actions 里先跑测试和类型检查，过了才构建发布 |
| 用命令行往文件里写带反斜杠或转义的内容，写进去的和我以为的不一样 | 这样的内容用写文件的工具写；写完跑一遍类型检查 |
| 任何「等一下再做」的动作（页面启动时的判断、确认框的确认、读到一半的文件），做完以后情况可能已经变了 | 动手之前记下当时是哪个项目（session），回来先核对，对不上就不做 |
| 我以为测试在测 A（卡住读取），其实卡住的是更早的一步（判断目录） | 测试里的「卡住」要卡在真正想卡的那一次调用上，数一数是第几次 |
| 页面每 5 秒读一次，读成功就把错清了，写失败的提示活不过 5 秒 | 错分两种：读的错，下一次读成功就清；要人处理的错（写失败、被拒绝、目录打不开）留到人处理为止，读出错也不许盖掉它 |
| 轮询读到一半时点了更新：那一轮读到的是写以前的文件，更新完反而亮「有更新」 | 写完先等在途的那一轮读完，再读一轮 |
| 抽屉里的内容是点开那一刻读的，之后文件变了它不知道 | 轮询重读时把开着的详情也重读一遍；读不出来、那张卡没了、换了页面，就关掉抽屉 |
| 先点甲再点乙，甲那一轮比乙晚结束，把乙的覆盖了或者清了乙的「正在读」 | 每次读详情记一个编号，回来先核对；对不上就丢掉，也不许动别人的状态 |
| 项目文件夹被移走、浏览器清了数据：页面一声不响地回到入口页 | 每条走不通的路都有一句说法和一个走得通的下一步。按钮写该做的事：「选择目录」，不是「重试」 |
| 页面一打开先画入口页，再换成「请用 Chrome」，闪一下 | 加一个「正在启动」的状态，这一段什么都不画 |
| 不备份就改写一个已有的文件（根 AGENTS.md），它可能根本不是 UTF-8 | 按字节读，认得出 UTF-8（带不带 BOM 都行）才动，BOM 写回最前面；认不出就停下，并说清楚另存成什么 |
| 开发服务器放行了仓库根，`.zcode/` 里的东西跟着读得到；拦截名单写成了 `.zcode/**`，看着对，一条都拦不住 | Vite 拿绝对路径匹配名单：带斜杠的模式要自己写全（`**/.zcode/**`），不带斜杠的它才自动加前缀。不凭印象写，起一个真的开发服务器试 |
| 新补的测试全绿，把修复撤掉还是全绿 | 补完测试做一遍变异检查：把修复临时撤掉跑，确认对应的测试会红，再恢复 |
| 假目录每次取子目录都给一个新对象，在它上面装的替身不生效 | 假目录对同一个子目录给同一个对象，和浏览器的句柄一样 |
| 块注释里写了文件的通配模式（两颗星加斜杠），注释被提前关掉，整个文件解析失败 | 含「斜杠加星」的内容用行注释 |
| 想验证「BOM 还在」，用默认的方式解码，解码器悄悄把 BOM 吃了 | 直接比字节，或者解码时让它留着 BOM |
| 不带 BOM 的 UTF-16 恰好是合法的 UTF-8，严格解码拦不住，文件被当成 UTF-8 改写了 | 认编码不能只靠「解码成功」：正文里有零字节就不是 UTF-8 文本 |
| 新加的操作要先走一趟浏览器的数据库，页面的更新排在它后面 | 页面先更新，存储放后台。不只是慢：测试里上一个用例的后台操作会回来改下一个用例的状态 |
| 测试时好时坏，单跑那个用例又总是过的 | 先找有没有跨用例的后台操作（用例里没等到的东西，会在用例结束后回来）。改完全量连跑几遍再下结论 |
| 断言「清掉了」，可造的数据里本来就是空的，清没清都一样 | 造数据时让两种结果有区别：先断言里面原来有东西，再断言被清掉 |
| 测试只看状态变化的序列，不看第一次画出来的是什么 | 包一层组件，在 App 渲染之前把当时的状态记下来 |
| 验收单里有两步要「页眉亮着有更新的项目」，前面的步骤已经把它更新掉了，人按字面点不下去 | 每一步写清开始时的状态，要什么状态就先造出来。写完验收单自己顺着走一遍 |
| 拦截名单是整份替换的，少抄一项（Vite 的默认项）也不报错 | 名单整份比对，不用「包含」 |
| 复制进来的文件在仓库里是 LF，工作区里还是 CRLF：页面写出去的是 LF，拿 `diff` 核对源头会报不一致 | 加了 `.gitattributes` 以后把工作区重新检出一次；核对前用 `git ls-files --eol` 看一眼 |
| 我说「存储出错照常工作」改完了，其实只盖住了测试里模拟的那一种；真浏览器里是两种一起坏，先坏的那种没兜住 | 兜底要从最外层包起（连取 `localStorage` 这一步都会抛错）；每一样存储失败各写一条测试 |
| 等浏览器存储的函数有时候永远不返回 | 事务除了「出错」还有「被中止」（磁盘满时只发这一样），两样都要接，接了都要返回 |
| 让页面等「记住目录」这种只是方便下次的事 | 先做要紧的（打开目录），方便的事放后台 |
| 撤掉修复的检查只撤了大块的保护，到处都有的小防护（核对是不是同一个项目）一处没试 | 把每一处核对当成一个防护，逐条撤、逐条看红不红 |
| 在全局原型上装的替身没还原，同一个文件里别的异步测试会集体卡住，时好时坏 | 能不去动全局就不动（把更外层的入口整个换成假的）；动了必须还原，改完乱序跑几遍 |
