# 旧版网页系统的经验

> 出处：旧仓库的 `.oht/knowledge/topics/网页系统.md` 和提交记录。那个文件 2026-11-24 随旧内容删掉了，这是从 git 历史取回原文后摘的，只留对新版还适用的。

## 做法

- 纯前端可行，不做本地薄服务。人 2026-11-03 定的，DJUI 已验证。
- 置入的核心写成纯函数，写文件的接口通过参数注入，才测得动（T0004）。
- 每 5 秒轮询刷新。
- 容器：nginx 托管静态产物，端口 7330；`index.html` 不缓存，带内容哈希的 assets 长期缓存。

## 入口块

- 根 `AGENTS.md` 的入口放在开头。放在末尾人看不见，AI 工具读长文件还会截断（T0040）。
- 入口要防重复：文件里已有 `.omt/AGENTS.md` 字样就不再插（T0040）。
- 入口块不进「框架文件被改过」的比对，因为文件正文是项目自己的，随时会改（T0035）。

## 界面

人的反馈很一致，前后给过好几轮：

- 卡面只留标题和编号，其余信息进了弹层（T0015、T0017）。
- 看板再极简：卡面只留标题和关键信息（人反馈）。
- 卡片详情只显示整理好给人看的（人反馈）。
- 人话位：卡片只给人看四句，机器标识不上主视觉（T0010）。
- 错误提示人话化，技术细节只进控制台（T0044）。人定的规矩：提示都面向用户，不显示不重要的信息。
- 视觉令牌集中在一处（T0023）。
- 界面用 antd 的成熟组件和规范（T0012）。
- 归档倒序，最多 50 张（T0026）。

## 踩过的坑

- Chromium 拦一批扩展名的写入，备份写成 `.bak` 会失败。旧版把备份改到了 `.upgrade-bak/` 目录（T0043，2026-11-05）。内存沙箱里复现不了。新版不备份，但名单上的文件名要先过检查，见「浏览器拦截的文件名」。
- 单元测试的沙箱和真实目录的行为不一样，只有真机能验证（T0043）。

## 新版没有沿用的

- 内置内容靠生成脚本从母本抄一份（`gen:template` 生成 `bundle.gen.ts`）。新版改成直接读入仓库里的原文件，不留第二份副本。这是新的做法，照 DJUI（`editor/frontend/src/lib/bundledAssets.ts`，用 Vite 的 `?raw` 导入），不是旧版经验。

- 版本号三处同值（VERSION 文件、根 `AGENTS.md` 标记行、代码里的常量），每次发版都要同步，是最费工的地方。新版不设版本号，靠逐份比对内容。
- 备份、哈希清单、更新前比对并停下。人定了始终覆盖。
- 流程图（环形画布）、看板列、多角色。旧版是围着循环工程建的。
