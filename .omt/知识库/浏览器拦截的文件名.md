# 浏览器拦截的文件名

> 查于 2026-11-24，Chromium 主分支。来源见文末。这张表会随 Chromium 版本和 Safe Browsing 的线上更新变，用之前复查。

## 结论

oh my task 往真实目录写文件时（初始化、更新），下面这些文件名 Chromium 不让建，会报 `Name is not allowed`：

| 类别 | 扩展名 | 在哪些平台上 |
|---|---|---|
| 固定封 | `lnk`、`scf`、`url` | 全部 |
| 下载文件类型表里标为危险的（`.local` 有例外，不封） | `cfg`、`dll`、`ini`、`manifest`、`scf` | 只在 Windows 上 |
| 同上 | `dng` | 只在 Android 上 |
| 扩展名是 CLSID 形状 | `{` 开头、`}` 结尾 | Windows 的隐患，检查不分平台 |
| 旧版真机上遇到过，当前表里没有 | `bak` | 这台机器是 Windows |

此外它还查：名字非空、不含路径分隔符、末尾不是点；文件名在当前平台合法（如 Windows 的保留名 `CON`、`NUL`）。这几样单测里不测，靠真机。

标为「允许，但要在用户的操作里」的不拦，所以 `.py`、`.js`、`.sh`、`.bat`、`.cmd`、`.ps1` 都能写。`.md` 在表里，但不危险；`.yaml` 不在表里。

oh my task 自己的检查（`app/src/framework/blocklist.ts`）从严：上面这些不分平台都拦，连 `bak` 也拦。

## 为什么单测测不出来

沙箱文件系统（测试用的内存目录同理）只查名字非空、不含分隔符，不查后面几样。只有真实目录句柄会走完整的检查。

## 查法

这台机器连不上 Chromium 的源码站，连得上 GitHub 镜像 `chromium/chromium`（会限流，遇到 429 等一下再试）。读三处：

- `content/browser/file_system_access/file_system_access_manager_impl.cc` 里的 `IsSafePathComponent`
- `chrome/browser/file_system_access/chrome_file_system_access_permission_context.cc` 里的 `IsFileTypeDangerous`
- `components/safe_browsing/content/resources/download_file_types/download_file_types.asciipb`：414 个扩展名的危险等级

`download_file_types.asciipb` 里的危险等级，2026-11-24 统计：

- 危险，7 个：`cfg dll ini local manifest scf dng`。其中 `dng` 只在 Android 上，其余六个只在 Windows 上（表里每个条目自带 `platform_settings`）
- 允许，但要在用户的操作里，221 个
- 其余 186 个不危险
