# 框架文件在业务项目里只读，更新时整份覆盖

任务系统的文件分两种。框架文件每个业务项目都相同（如 `.omt/AGENTS.md`、`默认工作流.md`）；项目文件是业务项目自己长出来的（术语、长期决策、知识库、业务工作流、项目规则、需求和任务夹）。原 SOP 允许业务项目改 `默认工作流.md`，那样更新时就得合并项目的版本和源头的版本。所以定成：业务项目里不改框架文件，更新时整份覆盖，项目文件不碰（根 `AGENTS.md` 只在开头补入口块）。

框架本身的成长归维护者。用户在业务项目里发现默认工作流缺什么，不在项目里记经验，而是作为需求提给 DJTASK，由维护者在源头走任务流程改原生提示词，再由更新发给所有项目。

## 后果

- `默认工作流.md` 的「固定新东西」表要改：踩过的坑、流程缺步骤，只写进业务工作流；关于默认工作流本身的，业务项目里不写。
- `默认工作流.md` 要加一条：业务项目里框架文件只读。
- 这两处改的是流程，由人在验收时确认。
