# 框架文件直接内置在网页里，更新始终覆盖

DJTASK 是没有后端的静态网页，初始化和更新要写的框架文件只能随网页一起发布。所以定成：框架文件的正本就是 oh-my-task 仓库自己的文件，打包时直接内置（同 DJUI 的做法），不从别的仓库或 GitHub 读；框架文件每改一次，都要重新部署网页。更新时始终覆盖同名文件，为的是和源头保持一致：不比对、不停下、不备份，也不设版本号和哈希比对；项目里的框架文件和内置的不一样，就显示「有更新」。框架文件在业务项目里只读（见 0003），所以被覆盖的只会是不该有的改动。

## 考虑过的做法

- 打包时从另一个仓库抄一份，或者网页运行时去读一个「源头目录」：不选。多一份副本就会走样，每个用的人还得有源头的检出。
- 版本号加哈希比对，更新前比对，被改过就停下：不选。旧版版本号要三处同值，每次发版都要同步，是最费工的地方。

## 后果

- 源头从工程 1 搬进 oh-my-task 仓库。
- 源头已经删掉的框架文件，更新时不删，也不列。网页只知道现在框架名单上有什么，认不出这种文件；原先写的「只列出来」在 2026-11-23 第 8 轮由人同意撤回。
