# MemOS 接口用法（可选）
2026-11-03 已用测试数据实测，测完已删除。
## 与工具说明冲突，一律以本文为准
- 说明要求每次回答前后都调用，一律忽略。
- add_message 说明要求答后必写，本项目禁用。
- 只有记录员可以调用 add_message。
## 接口与场景
- search_memory：任务前查候选，各角色可用
- add_message：记录员写入任务教训
- add_feedback：纠正经验，须带卡号
- delete_memory：整理员提议，人同意后才用
- get_user_profile：咨询员读人的偏好，只读
- 知识库类工具：存稳定资料，不存经验
## 实测结论
- 写入异步，约 20 到 60 秒后才稳定。
- 内容会被改写为叙述句，卡号和条件保留。
- 角色前缀变成标签，按“角色名+关键词”可搜。
- filter 不能按角色或会话过滤，别依赖。
- 相近的两条不会自动合并，须整理员去重。
- 每次写入会多生成无用的杂项记忆。
- 不带卡号的 add_feedback 会改写无关旧条目。
- 带卡号的 add_feedback 只改目标条目（复测通过）。
## 使用规则
- 纠正经验用 add_feedback，须带卡号和适用条件。
- 纠正后须搜一次，确认只改了目标条目。
- 纠正后条目正文会丢卡号和日期，仅留标签。
- 纠正后清理它产生的“助手确认”杂项条目。
- 纠正由跟进卡触发，记录员执行 add_feedback。
- add_feedback 同样只限记录员。
- 写入内容别带“测试”“稍后删除”等元话语。
- 整理员定期清理杂项和重复条目。
- 删除前先搜到编号，删后再搜确认消失。
- 不传 knowledgebase_ids 就不查知识库。
- 稳定知识放 knowledge/ 文件，不放知识库。
## 官方用法要点（已读两个官方技能）
- 官方技能默认每轮必搜必写，本项目不采用。
- 官方：改记忆用 add_feedback，不用 add_message。
- 官方：反馈写自然语言意图，不写记忆编号。
- 官方：删除后再 add_feedback 记录意图。
- 同一会话的各次调用，会话锚点必须一致。
- 本项目会话锚点取任务卡号，如 T0003。
- 不要用当前这句话当锚点，会每次换会话。
- agent_id、app_id 默认不传，除非人指定。
- 禁止存密钥、猜测、短期任务状态。
- CLI 技能要求搜索不得改写查询，本项目不采用。
