## 原话
"归档清单倒序，注意'最大长度，不能无限显示，导致卡。'"（人，2026-11-03）

## 需求
现状（2026-11-03 定稿核实）：`app/src/lib/scanTasks.ts` 按文件名升序排卡（`file.localeCompare(…, 'zh-CN')`），流程图右侧「已归档」面板（`FlowView.tsx` 的 `data-flow-archive`）与看板「已归档」列（`Kanban.tsx` 的 recorded 列）按此顺序原样全量渲染（T0001 在前、无上限）；App 每 5 秒轮询全量重渲染，归档卡一多列表无限增长、越刷越卡。

**修法（与 T0030 已落地惯例对齐）：**

1. 新建 `app/src/lib/archiveList.ts`，只承载归档清单的呈现契约，导出两项：
   - `ARCHIVE_LIMIT = 50`（归档清单上限常量）
   - `archiveMoreText(hidden: number, limit: number = ARCHIVE_LIMIT): string`，返回 `更早 ${hidden} 张已归档未显示（仅显示最近 ${limit} 张）`
   倒序+截断逻辑不在此重写：两视图一律复用 T0030 已落地的 `capNodeCards`（`lib/nodeCards.ts`，按 id 数字部分降序取前 N 张并返回 hidden 计数，T0030/A1 已锁定）。禁止在任何组件或 archiveList.ts 内重写同义排序——一份逻辑一个主人；T0030 当初把两函数分立是为并行卡互不牵连，该卡现已进入 review，本卡收敛。
2. `FlowView.tsx` 归档面板（`data-flow-archive="true"`）：`const archiveView = capNodeCards(buckets.archive, ARCHIVE_LIMIT)`，改渲染 `archiveView.shown`；`archiveView.hidden > 0` 时面板底部渲染 `<div className="flow-panel__more" data-flow-archive-more="true">{archiveMoreText(archiveView.hidden)}</div>`。样式复用 T0030 已入库的 `.flow-panel__more`（居中、12px、灰），**index.css 无需为归档面板追加规则**。
3. `Kanban.tsx` recorded 列：`const recordedView = capNodeCards(grouped.recorded, ARCHIVE_LIMIT)`，改渲染 `recordedView.shown` 清单行；`recordedView.hidden > 0` 时行列表底部渲染 `<div className="kanban__more" data-recorded-more="true">{archiveMoreText(recordedView.hidden)}</div>`。`index.css` 追加 `.kanban__more`（居中、12px、灰色 #9ca3af，与 `.flow-panel__more` 同款）。**列头计数 Badge 仍显示全量 `inColumn.length`，不改**（与 T0030 节点徽标同口径：截断只在渲染层，buckets/grouped 保持全量事实，计数才有来源）。
4. `Kanban.tsx` 头部锁定契约注释补一句「recorded 行截断到最近 50 张 + data-recorded-more 提示」（仅注释，签名零改动；先例 T0030 改 flowMap.ts 头注）。

**约束：** 不改任何既有测试文件（本卡新测试由检查员新增）；不改 `data-flow-archive`、`data-recorded-row`、`data-card-id`、`data-flow-card-id` 等已锁定 DOM 属性语义（新锚 `data-flow-archive-more`、`data-recorded-more` 为新域，与既有域零交集）；不改 `scanTasks.ts` 排序、`nodeCards.ts`、`KANBAN_COLUMNS` 与各列既有排序；两视图的上限与提示文案必须同源（都取 archiveList.ts），禁止各自硬编码。

**技术取舍留档（咨询员自治，2026-11-03）：** ①砍原稿的 `latestArchived`、复用 `capNodeCards`——行为完全同构（id 数字降序+slice+hidden 计数），另立即成同逻辑双主人，T0030 分立的唯一理由（并行卡互不牵连）已消失；②上限 50 对齐 T0030 未开始面板口径（人 2026-11-03 当面定的「截 50+更早提示」惯例），两视图统一取同一常量；③「更早」提示做成纯文本不可点——归档区定位是「最近动态」速览，全量历史在任务文件与看板本来可查，不为它新造展开交互（同 T0030「更多」提示的假设）；④排序键沿用 id 数字序而非归档时间——任务卡 id 单调递增且是既有唯一可靠序（capNodeCards 已锁），不为此卡新造时间字段。

## 复述卡
1. 理解：归档清单倒序（新在前）只显示最近 50 张，流程图与看板一致，防堆积后轮询越刷越卡。
2. 做：截断复用已落地的 capNodeCards；新建 archiveList.ts 放上限与提示文案；两视图渲染前 50 张，超出显示「更早 N 张已归档未显示」。不改列头总数、其他列排序。
3. 例：120 张归档卡→各显示 T0120→T0071 共 50 张，提示「更早 70 张已归档未显示」。
4. 拆分：无。
5. 待你定：无。
