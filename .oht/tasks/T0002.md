## 需求
把 oh-my-task 迁移为单目录形态，产物同时作为初始化功能的模板形态。

目标结构：
```
oh-my-task/
  AGENTS.md            # 仅一行引用：指向 .oht/AGENTS.md（内容自拟，≤3 行）
  app/                 # 网页项目代码（T0003 建，本卡不动）
  .oht/
    AGENTS.md          # 调度员入口（原根 AGENTS.md 内容）
    PROTOCOL.md
    roles/             # 8 个角色文件原样迁入
    scripts/           # check-card.py、check-size.py，内部路径修正
    tasks/             # 数据区，含现有任务卡
    knowledge/         # 数据区：rules.md、log/、topics/
```

约束：
- 只读区=框架文件（.oht/AGENTS.md、PROTOCOL.md、roles/、scripts/、tasks/_template.md、knowledge/topics/_template.md、knowledge/rules.md 的结构约定），AI 修改须人批准；数据区（tasks/ 卡片、knowledge/log/、local/）正常读写。
- 根目录除 AGENTS.md、app/、.git、.gitignore、.zcode 外不得有循环工程文件。
- 迁移是搬移+路径修正，不改框架文本内容（check-size.py 约束须仍然全绿）。
- 脚本默认路径全部改到 .oht/ 下（从仓库根运行 `python .oht/scripts/check-card.py .oht/tasks/T0002.md` 通过）。
- .gitignore 增补：tasks/.lock 仍忽略。
- README.md 若提及旧路径，同步修正。

## 候选教训
- 2026-11-03｜T0002｜git 查 rename 是否纯搬运时｜`git show <提交> -- 新路径` 会因旧路径不在过滤范围而显示成 new file，`git diff <提交>^ <提交> -- 旧路径` 会显示成全量删除；须新旧双侧路径同给，或直接看 `git diff -M --name-status` 的 R100，diff 体增删行数才是真内容变化。｜0｜候选
- 2026-11-03｜T0002｜核对检查脚本"零超限"时｜路径过滤导致 glob 为空时检查器会以 0 超限假绿（如迁移后 `check-card.py .` 在根下找不到 tasks/）；判定脚本通过须确认它真的扫到了目标集合，最好另喂一张坏卡证伪检查器仍能报错。｜0｜候选
