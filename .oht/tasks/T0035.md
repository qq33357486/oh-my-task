现状缺口：页眉只有标题+目录名 Tag+刷新，选定目录后全站无更换入口；无任何版本显示与更新机制；

### 1. 菜单栏（页眉改造，A1）
- 页眉左侧：logo + 标题「循环工程指挥台」（看板视图已删，旧标题「循环工程任务看板」名不副实，自治决策 b）+ 目录名 Tag（app-header__root 契约不变）。
- 页眉新增两个菜单入口：`[data-menubar-item="文件"]`、`[data-menubar-item="帮助"]`，AntD Dropdown trigger click（DJUI TopBar 同款）。
- 文件菜单：打开/更换目录…（=store.pick，readwrite 单入口不变）；「最近项目」分组（Menu type:'group' 内联展开，非嵌套子菜单）；关闭项目（清当前句柄回落地页）。
- 帮助菜单：检查工程更新（手动全量复检）；关于（弹窗显示应用版本=package.json version 与内置框架版本=FRAMEWORK_VERSION）。
- 右侧保留既有刷新按钮（T0025 契约不动）。

### 2. 项目打开/更换（A2、A3、A4）
- lib/recentProjects.ts：pushRecent 去重置顶、上限 RECENT_LIMIT=8 从尾部截断、空名不动；loadRecent/saveRecent 走 localStorage['oht.recentProjects']，坏数据自愈 []。
- projectContext 扩展（T0003 裁剪版之上）：pick() 同时持久化默认 key 'projectRoot' 与分 key 'root@<目录名>'；switchTo(name) 从分 key 取句柄覆盖默认 key 后返回（无则 null 不动默认）；close() 只清默认 key，分 key 保留（fsAccess 增 deleteHandle）。
- 菜单「最近项目」分组列出最近项目（≤8），当前项目项带「（当前）」后缀；点击非当前项=switchTo 成功后整页 reload（DJUI 验证过的干净姿势，jsdom 下 reload 为 no-op，断言落默认句柄已切换）。
- 「关闭项目」：projectContext.close() + store 回落地页态（PickPage 重现）。
- pick 成功后 pushRecent(目录名)。

### 3. 内置框架副本生成式（A5，消灭漂移）
- 新增生成脚本（app/scripts/gen-template.py，读母本 .oht/ 与 scripts/pack.py 的 FRAMEWORK_FILES 唯一权威清单），产出 src/template/ 副本文件与 src/template.ts 导出；npm script 挂 gen:template；产物入库可 diff、重跑幂等。实现方式自由，锁定的是产物契约（下条）。
- src/template.ts 新增导出：FRAMEWORK_VERSION（=.oht/VERSION 同值）、FRAMEWORK_FILES: {path, content, sha256}[]（path 集合=pack 清单 21 项；content 与仓库母本逐字一致；sha256 为十六进制摘要，供 .manifest 直写）、RULES_SKELETON（装机空骨架，install.py 同语义，绝不是母本业务 rules.md）。
- 既有 TEMPLATE_FILES 改为派生自 FRAMEWORK_FILES（.oht/ 下 20 项，root AGENTS.md 由 runInit 语义自理），手拷退役。

### 4. 更新机制（A6、A7、A8、A9，语义与 install.py 同源）
- lib/frameworkUpdate.ts 纯函数：compareSemver；evaluateFramework({installedVersion, bundleVersion, manifestMismatch}) 五态：notInstalled / outdated / upToDate / newerThanBundle（防降级态，提示刷新网页获取新前端）/ modified（版本同但框架文件被改动）。
- fs/frameworkWriter.ts：
  - readFrameworkState(root, {verifyManifest})：读 .oht/VERSION 为 installedVersion（无 .oht/ 或无 VERSION → null）；verifyManifest=true 时按 .oht/.manifest 逐文件比对 sha256（缺 manifest 不误报）。
  - upgradeFramework(root)：防降级先于一切写（目标新于内置 → ok=false、reason 含「降级」、目标逐字节零改动）；全量写 FRAMEWORK_FILES（相同=same 不落盘不留 .bak；不同=旧内容先备份 <路径>.bak 再覆盖）；业务不动（tasks/T*.md 除模板、knowledge/log、local、tests 零写删；骨架 .gitkeep×4 与 rules.md 缺则补、有不覆盖）；宿主 AGENTS.md 首行标记行只更新版本（用户自己的无标记文件原样保留且不入 manifest）；写 .oht/.manifest={version, files:哈希}。
- store 扩展：frameworkState 五态（null=未查）；每次成功 refresh 后静默轻量评估（只读 VERSION，不做 manifest 对账）；「检查工程更新」手动全量（对 manifest 账，能发现 modified）。
- 徽章与弹窗（A8）：outdated（或 modified/newerThanBundle）时页眉出现 `[data-update-badge]` 橙色徽章，aria-label 含「目标版本与内置版本」两版本号；点击弹更新弹窗，含版本变迁与「全部更新」按钮，执行 upgradeFramework 后复检、徽章消失；upToDate 无徽章。newerThanBundle 文案提示刷新网页而非更新。
- 初始化统一（A9）：runInit 产物补全（scripts 6 个、.oht/VERSION、.oht/.manifest；rules.md 改写 RULES_SKELETON）；runInit 三参签名、幂等拒绝、宿主 AGENTS.md 追加语义等 T0004 锁定契约全部不变（initProject.test 改写后 A2/A3 用例即证）。

### 5. 既有契约与锁定测试
- 不回归：T0023/A5 页眉 logo+root Tag、T0025 刷新按钮、T0009 入口单流/初始化分支、T0004 幂等/追加行、T0030~T0034 流程图全部契约。
- 授权改写（依据=本卡人在场定稿确认；先例 1575d9d、T0033「卡即批准依据」；改前 sha1 96c301dca1ee41f565c4ebe6729c8612a310a8b0）：initProject.test.ts 产物清单断言 roles 10→9（去 dispatcher-intake）、scripts 2→6、新增 VERSION/.manifest/RULES_SKELETON 断言；已随卡改写交付，签名与幂等/追加语义断言原样保留。

## 复述卡
