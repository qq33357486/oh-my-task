我正在尝试给自己打造一套循环工程的方案
之前我在别的绘画里已经画了这个画布，并在你当前的项目当中，构建了最初级版本的提示词，也就是说，构建了循环工程。

接下来我希望的是，在你这里初次尝试启动这个循环工程，并且完成循环工程整个系统的开发。提示词只是它的一部分

它应该还会配套一个部署在容器上的网页系统。部署完成后，可以进行以下操作：
1. 选择一个目录（例如选择一个工程），初始化这套循环系统的提示词；
2. 更新系统，并读取磁盘上循环工程里涉及的任务，将其显示在画布上。

目前我只有一些初步的想法，还不够完善，需要在你我的配合中逐步完善这套工程。同时，这一次的开发旅程也是在验证这套系统的可行性。

接下来我就会给你讲一些我的初步的想法。

### 环境
过往的项目里，有一个叫DJUI的，`D:\git\DJUI` 它有一个特性：可以通过网页打开本地目录进行阅读，并进行来回的交互。

目前我对这个项目的期望，也就是它的实现方式，是做一个很轻的前端，本身没有后端功能。但是它可以进行更新，让用户在上面查看当前有哪些任务，或许也会有简单的交互（但目前我还没想到需要什么样的交互），因为真正的工作都是在本地的 Agent 工具和 AI 之间完成的。

## 需求
经拷问（人在场，grill-me 十问）定案：

1. 形态：纯前端 + 浏览器 File System Access API 读写本地目录（DJUI 模式），无后端，仅支持 Chrome/Edge。
2. 与 DJUI 关系：全新实现，拷贝 DJUI 的 `editor/frontend/src/fs/fsAccess.ts` 通用文件层与句柄持久化（IndexedDB）模式；技术栈 React 18 + AntD 5 + Zustand + Vite + TypeScript。
3. 容器化：本地 `npm run dev` 为主，交付含 Dockerfile（Nginx 托管静态 dist）。
4. 目录规范化：本仓库迁移为单目录 `.oht/`；根目录 AGENTS.md 只留一行引用；`.oht/` 内分只读区（框架：AGENTS.md、PROTOCOL.md、roles/、scripts/、模板）与数据区（tasks/、knowledge/、local/）；迁移产物形态 = 初始化功能生成的形态。
5. 网页职责边界（硬约束）：网页只做两件事——读本地任务文件显示、对目录初始化写文件；不承担任何主动任务；定时角色（巡检员、整理员）全部由本地 Agent 侧（如 ZCode 自动化任务）配置，初始化产物只需附开启指引。
6. 展示：看板，按 status 分列（new/tests/ready/review/done/need_human），need_human 列高亮置顶（对应【关键】"人类要能看到自己该注意的"）；轮询刷新（约 5 秒）；点卡看全文。
7. 模板来源：网页内置模板副本（源头本仓库，发版同步），初始化=拷贝+按目标工程定制。
8. 第一版显示范围：只任务卡（含点开全文）；html 内嵌、知识库入口等后续。
9. 代码位置：本仓库 `app/`。
10. 初始化对宿主 AGENTS.md：无则新建（一行引用），有则只追加一行引用，不动其余内容。

拆分（大需求，origin=split）：
- T0002 框架迁移 .oht/（先做，定结构与模板形态）
- T0003 网页系统：骨架+文件层+看板
- T0004 初始化功能+引导卡+Dockerfile
依赖：T0002 先行；T0003、T0004 之后同泳道成批。
