## 原话
"之前是由 GLM 完成了整个项目的初始化和页面。我希望你检查是否有优化空间，特别是页面能否更漂亮，还有那些小修错误。"（人，2026-11-03；范围定为"小修 + 全站视觉统一"，拆三卡，本卡是第 1 张：工程小修。）

## 需求
目标：让 `app/` 的类型检查与测试输出变干净。本卡**不改任何页面外观**。体检基线：vitest 60 项全绿；`npx tsc --noEmit` 报 5 处错；vitest 输出 149 条 act 警告和 1 条 jsdom 报错。

逐项做法（实现员照此做，不必另想方案）：
1. **scanTasks.ts(28) 与 scanTopics.ts(22) 报 `Property 'values' does not exist on type 'FileSystemDirectoryHandle'`**：根因是 TS 的 lib 缺异步迭代声明。修法只改 `app/tsconfig.json`：`lib` 数组追加 `"DOM.AsyncIterable"`（变为 `["ES2020","DOM","DOM.Iterable","DOM.AsyncIterable"]`）。不要给这两个文件加 `as any`，不要新写 d.ts 去补 `values`。若加了 lib 仍报错，再在 `src/global.d.ts` 里以 `interface FileSystemDirectoryHandle { values(): AsyncIterableIterator<FileSystemHandle>; }` 补，二选一，先试前者。
2. **kanban.test.tsx(12)、cardTitle.test.tsx(27)、visual.test.tsx(36) 报 `title?: string | undefined` 不可赋给 `ParsedCard.title: string`**：这三处测试夹具把 title 推成了可选。修在夹具构造处：给 title 一个默认值 `''`（例如辅助函数参数写成 `title = ''`，或对象字面量显式写 `title: ''`）。**这三个测试文件属已锁定测试**：只允许改夹具的类型/默认值这一行级别的类型修复，不得改任何断言、用例名、用例数量；改完 `npx vitest run` 的通过数必须仍 ≥ 60。
3. **act 警告（"The current testing environment is not configured to support act(...)"）**：在 `app/src/test/setup.ts` 顶部加一行 `(globalThis as { IS_REACT_ACT_ENVIRONMENT?: boolean }).IS_REACT_ACT_ENVIRONMENT = true;`。加完重跑 vitest 数警告；若仍有残余，只允许继续在 setup.ts 层处理（例如对仍触发的异步 store 更新，不动测试文件）。若 setup 层确实清不到 0，把残余条数和来源测试写进"进度"，转 need_human 让人定（不要去改锁定测试断言）。
4. **`Error: Not implemented: window.getComputedStyle(elt, pseudoElt)`**：jsdom 对第二参数（伪元素）未实现，AntD 会传。在 `setup.ts` 里包一层：保存原 `window.getComputedStyle`，重写为 `(elt) => orig(elt)`（丢弃 pseudoElt 参数）。
5. `app/package.json` 的 scripts 增加 `"typecheck": "tsc --noEmit"`。

禁止项：不改任何 `src/components/*.tsx` 的渲染输出与样式；不升级依赖；不改 vitest 配置里的 include；不加 `// @ts-ignore`、`as any` 去消错。
