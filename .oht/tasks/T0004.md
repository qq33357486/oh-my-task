## 需求
在 T0003 的网页项目上增加初始化功能，并交付 Dockerfile。依赖：T0002 完成后才能拷模板（模板=其 `.oht/` 产物剔除业务数据）；T0003 完成（app 骨架在）。

初始化流程（网页上选目标目录后执行）：
1. 写入 `.oht/`：模板内置副本（AGENTS.md、PROTOCOL.md、roles/、scripts/、tasks/_template.md、knowledge/ 空壳含 rules.md 与 topics/_template.md）。模板源=本仓库 .oht/ 框架区（只读区），放 `app/src/template/` 随代码提交；发版时从本仓库同步。
2. 宿主 AGENTS.md：无则新建（内容=一行引用 .oht/AGENTS.md）；已存在则仅在文件末尾追加一行引用，其余内容不动。
3. 生成业务数据区空壳：.oht/tasks/、.oht/knowledge/log/、.oht/local/。
4. 生成引导卡 .oht/tasks/T0001.md（status=new，type=引导）：内容教使用者三件事——怎么发第一个需求（对 Agent 说人话即可）、任务卡怎么流转（一行生命周期）、怎么开启定时角色（例：对 ZCode 说"给巡检员建每 2 小时的定时任务"）。
5. 幂等：目标目录已存在 .oht/ 时拒绝执行并提示，不覆盖任何文件。

约束：
- 初始化核心逻辑写成纯函数（输入=写文件接口抽象），与 File System Access API 解耦，供单测。
- 模板副本与框架母本不一致属正常（母本演化快于发版），但结构约定（.oht/ 布局）必须一致。
- 容器：Dockerfile（Nginx 托管 `app/dist/`，端口 7330）+ `.github/workflows/docker-publish.yml`（push master 触发，构建发布 GHCR，仿 DJUI）；本机不装 docker，本机直接 `npm run dev`。
