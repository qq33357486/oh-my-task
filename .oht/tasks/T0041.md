## 原话
不太对。如果已经被"初始化"的项目，之前遗漏了agents.md ，那加载的时候，应该要能够检测，并修复的。
通常，这种就是加载流程里，或者更新流程里，"数据迁移"要检查并完成的事情把？

## 需求
已初始化项目（有 .oht/）永远不会走初始化链路，宿主 AGENTS.md
的入口插入缺口无人补——老版本初始化的、写入失败的、用户删过的。
定位（人定）：属数据迁移，加载流程里检查并完成。
方案：refresh 扫描后 hasOht=true 时静默迁移——
- 读 .oht/VERSION 为已装版本（缺/非法 → 不迁，守恒不猜）；
- AGENTS.md 含 .oht/AGENTS.md 引用 → noop（T0040 防重复标准复用）；
- 首行已是版本标记行 → noop（升级链路管理域，防双标记）；
- 无 AGENTS.md → 新建入口块（版本=已装版本）；
- 有 AGENTS.md 无引用无标记 → 开头插入口块（版本=已装版本），
  原文逐字下移。
标记行写已装版本（非内置）：迁移不撒谎，后续升级只推版本行。
upgradeFramework 不动（T0035「无标记不碰」严格语义保留，迁移在
加载侧兜底覆盖——打开必经 refresh，更新前项目必被打开过）。

## 复述卡
1. 理解：已初始化项目打开时检测宿主 AGENTS.md 入口缺口并补插。
2. 做：migrateHostAgents 迁移函数+refresh 集成+版本取已装值。
3. 例子：老项目打开网页即补三行入口块，原文下移，幂等安全。
4. 拆分：迁移判定四分支（引用/标记/缺文件/需插入）各自独立。
5. 待人决策：无。
