## 需求
现状：需求节点不挂 new 卡，只渲染提示「未开始 N 张（见左侧面板）」（`FlowView.tsx` 内 `flow-node__hint` 块）；其余四环节节点直挂且无上限，堆积会挤爆固定 280px 节点高（T0027 引入）。人裁定推翻 T0019 时「new 不占画布」的旧映射约束：画布五环节节点一律直挂卡，堆多用「更多」计数提示。

**修法：**

1. 新建 `app/src/lib/nodeCards.ts`，导出：
   - `NODE_CARD_LIMIT = 4`（节点速览窗口常量）
   - `capNodeCards<T extends { id: string }>(cards: readonly T[], limit = NODE_CARD_LIMIT): { shown: T[]; hidden: number }`——按 id 数字部分（去前缀 T 后的数值）降序（最新在前），返回前 limit 张与隐藏计数；纯函数，无副作用，空数组返回 `{ shown: [], hidden: 0 }`。

2. `FlowView.tsx` 五环节节点统一改渲染（含需求节点）：
   - 每节点用 `capNodeCards(buckets.canvas[name])` 取 `shown` 渲染卡面；`hidden > 0` 时卡片区底部渲染 `<div className="flow-node__hint" data-node-more="true">更多 {hidden} 张</div>`（需求节点文案为「更多 {hidden} 张（见左侧）」，其余节点纯计数文案，不可点击）。
   - 节点头计数徽标 `flow-node__count` 仍显示该环节全量数（`buckets.canvas[name].length`），不改。
   - 删除现有「未开始 N 张（见左侧面板）」提示块。

3. 左侧「未开始」面板保留为完整清单（人在场已定）：
   - 渲染改 `capNodeCards(buckets.todo, 50)` 取 `shown`；`hidden > 0` 时面板底部渲染 `<div className="flow-panel__more" data-flow-todo-more="true">更早 {hidden} 张未开始未显示（仅显示最近 50 张）</div>`。
   - `.flow-panel__more` 样式复用 T0026 引入的规则（居中、12px、灰色）；若 T0026 未同批落地，本卡在 `index.css` 补同款规则（实现员取舍，留进度）。
   - 收件箱面板（need_human）不动。

4. `flowMap.ts` 头注第 13-15 行「画布挂卡另受 new 不占画布、进左侧未开始区」的表述同步改写为新契约（仅注释，锁定签名 `mapStatusToNode` 零改动）。

5. 锁定测试契约改写（本卡授权，检查员在 tests 阶段执行；先例 T0004/A4、T0018）：

   - 其余锁定断言零改动（`data-flow-todo` 面板存在且含 new 卡、三面板标题锚、节点序等均保持）。

**约束：** 不改 `mapStatusToNode`；不改 `data-flow-node`、`data-flow-card-id`、`data-flow-text`、`data-flow-todo` 等既有 DOM 锚；不改 `Kanban.tsx`；不改任何既有锁定测试语义（第 5 点授权的两处除外）。
